# ADR-001: Uso de SQLite para la persistencia

Fecha de creación: 2026-11-27  
Este ADR se crea en la Semana 10 para documentar una decisión previa. No se presenta como decisión original producida en un módulo anterior.

## Estado

Aceptada.

## Contexto

El proyecto necesita una aplicación local sencilla para gestionar citas de un consultorio pequeño. La infraestructura disponible no exige un servidor de base de datos separado.

## Decisión

Usar SQLite mediante `better-sqlite3`, con el archivo `backend/data/agenda.sqlite3`.

Evidencia: [db.js](../../backend/src/db.js), [README](../../README.md).

## Alternativas consideradas

La bitácora menciona SQLite como parte de la decisión inicial, pero NO EXISTE una tabla de alternativas registrada ni un documento previo que las compare.

Alternativas conservadoras disponibles para el proyecto:

- SQLite local: mínimo número de servicios y apropiado para una ejecución local.
- PostgreSQL/MySQL: mayor capacidad operativa, pero requieren servidor y configuración adicionales.
- Mantener datos solo en memoria: facilita pruebas pero pierde persistencia.

## Consecuencias

**Positivas:**

- Menor complejidad de instalación.
- Funciona localmente sin un servidor de base de datos externo.
- Permite pruebas y validaciones con Node.js.

**Negativas:**

- No está diseñado para acceso concurrente amplio.
- El acceso está limitado a localhost.
- NO EXISTE cifrado integrado en la configuración actual.
- El respaldo y la recuperación dependen de procedimientos documentados.
